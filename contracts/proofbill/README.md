# ProofBill contract

Rust/near-sdk contract for NFT Purchase Passes, bounded native testnet NEAR purchases and service refunds. Version 4 accepts a custom service total and an optional per-order price ceiling, with one active order at a time; v3 and single-use passes remain supported. Manual mode requires buyer approval for each delivery. Automatic mode uses explicit budget authorization and matching publisher delivery. Both mark Paid only after the seller-transfer callback succeeds; failed-payment retries require buyer approval. Use `infra/near/testnet-init.json` only for the declared project deployment; replace identities for your own deployment.

```sh
cargo near build non-reproducible-wasm --locked
cargo test --lib
cargo test --test test_basics -- --nocapture
```

The tool prints the resulting Wasm/ABI paths. Local Windows verification used WSL, an isolated `CARGO_TARGET_DIR`, and the pinned Rust toolchain. Sandbox receiver fixtures are local test-only Wasm; publisher evidence is synthetic in those tests. Actual provider verification lives in `workers/inference` and has separate testnet execution evidence.

The checked-in `abi.json` is generated by the pinned financial CI build and includes `create_flexible_budget_pass`, `configure_budget_agent`, `top_up_storage`, budget views and recorded order policies/ceilings. Its metadata identifies its exact Wasm hash. Always use `cargo near build`, which supplies the SDK's required `--cfg near`; a plain `cargo build --target wasm32-unknown-unknown` is not an equivalent contract build. Sandbox denial assertions check actual host error messages as well as refusal. Build from the intended revision and use that build's ABI with [the Rust source](src/lib.rs).

Contract ownership/payment state is authoritative. Publisher assertions are trusted offchain-verifier statements, not onchain hardware-quote verification. Private callbacks consume exact attempt results; unknown outcomes are not automatically retried or refunded.

Each order currently costs 0.010 testnet NEAR. Flexible budgets need to cover that quote, accept other atomic totals without a 1 NEAR ceiling, and start with at least 0.030 NEAR of separately funded storage backing. More backing may be attached initially or added by the owner as history grows. A conservative 1,400-byte allowance is checked before reservation; actual byte changes charge/release storage credit. A limit is an owner ceiling, not a user-set merchant price. Successful service refund closes the pass and returns remaining service funds, excluding prior seller payments and storage. Legacy v3 creation retains its original funding rule. See [the version-4 checks](../../docs/evidence/flexible-budget-contract.md). No mainnet-readiness or audit claim is made.
