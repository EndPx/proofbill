# ProofBill contract

Rust/near-sdk contract for NFT Purchase Passes, bounded native testnet NEAR purchases and service refunds. Version 3 supports a reusable service budget with one active order at a time; legacy single-use passes remain supported. Manual mode requires buyer approval for each delivery. Automatic mode uses explicit budget authorization and matching publisher delivery. Both mark Paid only after the seller-transfer callback succeeds; failed-payment retries require buyer approval. Use `infra/near/testnet-init.json` only for the declared project deployment; replace identities for your own deployment.

```sh
cargo near build non-reproducible-wasm --locked
cargo test --lib
cargo test --test test_basics -- --nocapture
```

The tool prints the resulting Wasm/ABI paths. Local Windows verification used WSL, an isolated `CARGO_TARGET_DIR`, and the pinned Rust toolchain. Sandbox receiver fixtures are local test-only Wasm; publisher evidence is synthetic in those tests. Actual provider verification lives in `workers/inference` and has separate testnet execution evidence.

The checked-in `abi.json` is generated by cargo-near for the version-3 build and includes `create_budget_pass`, budget views and recorded order policies. Its metadata identifies its exact Wasm hash. Always use `cargo near build`, which supplies the SDK's required `--cfg near`; a plain `cargo build --target wasm32-unknown-unknown` is not an equivalent contract build. Sandbox denial assertions check actual host error messages as well as refusal. Build from the intended revision and use that build's ABI with [the Rust source](src/lib.rs).

Contract ownership/payment state is authoritative. Publisher assertions are trusted offchain-verifier statements, not onchain hardware-quote verification. Private callbacks consume exact attempt results; unknown outcomes are not automatically retried or refunded.

Each order costs 0.010 testnet NEAR. A budget pass funds 1–100 orders and separately attaches storage backing of `0.030 NEAR + service budget`; actual per-pass storage credit is charged by byte growth. A successful refund returns unspent service funds, excluding prior seller payments and storage. Legacy single-use creation retains its separate 0.030 storage budget. No mainnet-readiness or audit claim is made.
